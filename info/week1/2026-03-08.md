## Routes implémentées

### PATCH /users/me
- Champs modifiables : `firstName`, `lastName`, `phoneNumber`, `dateOfBirth`, `newsletterSubscribed`, `billingAddress`
- Si `newsletterSubscribed` passe de `false` à `true` : `newsletterConsentDate` défini côté serveur (RGPD)
- Retourne le document mis à jour (sans `passwordHash`)

### DELETE /users/me
- Supprime le document en base
- Efface le cookie `auth_token` (`res.clearCookie`)
- Retourne 204 No Content

### PATCH /users/me/consents
- Met à jour `cookieConsents` : `marketing`, `functional`, `version`
- `cookieConsents.date` toujours défini côté serveur

## Règles respectées

- `passwordHash` jamais retourné
- `newsletterConsentDate` et `cookieConsents.date` toujours définis côté serveur
- `DELETE /users/me` efface le cookie auth pour invalider la session immédiatement

## Résultat des tests

PATCH  /api/users/me              →  200 + user mis à jour (firstName, phoneNumber, billingAddress)
