### Nouveaux fichiers créés

#### Slots
- `api/src/slots/schemas/slot.schema.ts` — Schéma Mongoose : `time` (HH:mm), `date` (YYYY-MM-DD), `maxOrders` (défaut 5), `currentOrders` (défaut 0). Index unique sur `{time, date}`.
- `api/src/slots/slots.service.ts` — Génération lazy des 32 créneaux (11:00–18:45, intervalles 15 min) au premier appel du jour. `getAvailableSlots()` filtre où currentOrders < maxOrders. `incrementSlot()` via `$inc`.
- `api/src/slots/slots.controller.ts` — GET /slots, protégé par JwtAuthGuard.
- `api/src/slots/slots.module.ts` — Exporte `SlotsService`.

#### Orders
- `api/src/orders/schemas/order.schema.ts` — Enum `OrderStatus` (pending/confirmed/ready/completed). Sous-documents `OrderItem` (productId, name, price, quantity, customization) et `OrderBillingAddress`. Champs Order : `orderNumber` (unique, format `OMM-YYYY-NNNN`), `userId`, `items[]`, `totalAmount`, `creditApplied`, `finalAmount`, `pickupSlot`, `status`, `billingAddress`, `loyaltyPointsEarned`.
- `api/src/orders/dto/create-order.dto.ts` — `pickupSlot` (IsString), `applyCredit` (IsBoolean, IsOptional).
- `api/src/orders/orders.service.ts` — `create()` : valide adresse de facturation, panier non vide, créneau disponible, éligibilité crédit → snapshot des items avec noms produits → calcul totalAmount/creditApplied/finalAmount/loyaltyPointsEarned → génère orderNumber → save. `confirm()` : valide statut pending + ownership → confirmed → incrementSlot → crédite points fidélité (déduit 50 si crédit appliqué) → ajoute entrée loyaltyHistory → vide le panier. `findByUser()` : trié par createdAt desc.
- `api/src/orders/orders.controller.ts` — Deux contrôleurs dans un même fichier : `OrdersController` (`@Controller('orders')`) pour POST /orders et PATCH /orders/:id/confirm ; `UserOrdersController` (`@Controller('users')`) pour GET /users/me/orders (évite la dépendance circulaire avec UsersModule).
- `api/src/orders/orders.module.ts` — Importe MongooseModule, UsersModule, SlotsModule, CartModule, ProductsModule.

### Logique métier clé

- **Snapshot au moment de la commande** : le nom du produit est résolu via `ProductsService` au moment de `create()`, pour que la commande reste cohérente même si le produit est modifié plus tard.
- **Numéro de commande** : `OMM-YYYY-NNNN` calculé à partir du comptage total des documents + 1.
- **Fidélité** : 1€ de finalAmount = 1 point. Crédit = 50 pts déduits, 5€ appliqués sur le total. Crédité uniquement à la confirmation.
- **Génération des créneaux** : lazy pour la date du jour, `insertMany` avec `ordered: false` pour gérer les race conditions silencieusement.

### Problèmes résolus

- **Dépendance circulaire** `UsersModule ↔ OrdersModule` : résolu en plaçant `UserOrdersController` dans `OrdersModule` avec `@Controller('users')` au lieu de toucher `UsersModule`.
- **Erreur TypeScript `never[]`** dans `slots.service.ts` : tableau vide inféré comme `never[]`. Résolu par annotation de type explicite.
- **Erreur Mongoose `create()` sur les commandes** : le typing DeepPartial de Mongoose était trop strict pour le tableau d'items. Résolu en passant à `new this.orderModel({...}).save()`.
